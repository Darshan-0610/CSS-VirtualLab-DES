PURPOSE

Aim

To study the Data Encryption Standard (DES) by understanding how a 64-bit plaintext block is transformed into a 64-bit ciphertext through an initial permutation, 16 Feistel rounds and a final permutation.

THEORY MADE SIMPLE

Understand DES at first glance

DES repeatedly rearranges bits, substitutes values and mixes the data with round keys.

64-bit block cipher
01

Prepare the key

The supplied key contains 64 bits. PC-1 removes the eight parity positions, leaving 56 effective key bits.

64 bits → 56 bits
02

Rearrange the plaintext

The 64-bit plaintext passes through the Initial Permutation (IP) and is split into two 32-bit halves: L₀ and R₀.

64 bits → L₀ + R₀
03

Perform 16 Feistel rounds

Each round expands the right half from 32 to 48 bits, XORs it with a round key, substitutes through eight S-boxes, applies the P-box, and combines the result with the left half using XOR. The halves then exchange roles.

32 → 48 → 32 bits
04

Swap and finish

After the sixteenth round, the halves are placed in swapped order and processed by the Final Permutation (FP) to produce the ciphertext.

R₁₆ || L₁₆ → ciphertext
Remember: IP and FP rearrange the 64-bit block. The 16 rounds mix the data with round keys. The key schedule produces sixteen 48-bit subkeys from the effective 56-bit key.

CORE CONCEPTS

Important DES terminology

Block size

DES processes data in 64-bit blocks. Longer messages require a defined block-handling method.

Effective key size

Eight parity positions are discarded by PC-1, leaving 56 effective key bits.

Feistel network

Each round uses the previous right half as the new left half and XORs the previous left half with the round-function output to create the new right half.

S-boxes

Eight fixed substitution boxes transform the 48-bit round-function input into 32 bits, introducing non-linearity.

Key schedule

PC-1, circular left shifts and PC-2 generate the sixteen 48-bit round keys.

Avalanche effect

A small input change can cause many ciphertext bits to change. Roughly half of the output bits changing is a useful statistical expectation, not a guarantee for every input.
